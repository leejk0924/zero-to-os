# 의도

이 프로젝트를 왜 하는지, 무엇을 얻으려는지를 적는다. 문서에 답이 없는 선택을 만났을 때 여기에 비춰 판단한다. 무엇을 어디까지 만드는지는 `docs/spec.md`에 있다.

## 왜 하는가

사용자는 백엔드 개발자다. OS에 대한 지식이 부족하다고 느끼고, OS를 알면 백엔드 일에 큰 도움이 된다고 본다. 그래서 OS를 처음부터 직접 만들어 가며 배우려 한다.

## 얻으려는 것

- 실제로 쓰는 OS를 대체할 수준은 아니어도, OS의 많은 부분을 내부까지 잘 아는 상태
- 다음 주제를 직접 만들어 보고 이해하는 것: 부팅, 메모리 관리, 가상 메모리, 프로세스, 파일 시스템, 네트워크, 소켓, 멀티플렉싱
- 동시성. 사용자가 반드시 다뤄야 한다고 정한 주제다.

## 사용자가 중요하게 여기는 것

- **부팅 과정부터 시작한다.** 전원이 켜진 순간부터 직접 만든다.
- **실제로 활용할 수 있는 쪽을 고른다.** RISC-V를 고른 이유도 라이선스 제약이 없고 활용할 곳이 많아서다.
- **읽으며 배운다.** 학습 내용은 대화가 아니라 옵시디언 노트로 받아, 사용자의 속도로 읽는다.
- **문서로 지시하고 문서로 남긴다.** 결정과 이유가 프로젝트 안에 기록되어 있어야 한다.

## 판단 기준

문서에 답이 없는 선택은 아래 순서로 판단한다.

1. 사용자가 그 부분을 직접 이해하게 되는 쪽
2. 백엔드 개발자가 실무에서 만나는 것(Linux, 서버)과 이어지는 쪽
3. 더 단순한 쪽

## 실패로 보는 것

- 동작은 하지만 사용자가 이해하지 못한 코드가 쌓인다.
- 학습 대상인 부분을 외부 크레이트가 가린다.
- 기능은 늘었는데 학습 노트가 따라오지 않는다.
