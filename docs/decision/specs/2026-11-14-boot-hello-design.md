# 1단계 설계: 부팅 → Rust 커널 진입 → 글자 출력

- 작성일: 2026-11-14
- 표시 규칙: **[결정]** 은 대화에서 사용자가 정한 것, **[제안]** 은 Claude가 채운 것(수정 가능)

## 의도

백엔드 개발자가 OS 내부를 깊이 이해하기 위해 OS를 처음부터 직접 만들어 본다.
실사용 OS를 대체하는 것이 아니라, 만들면서 배우는 것이 목적이다.

전체 여정은 주제별 단계로 나누고, 이 문서는 그 첫 단계만 다룬다.

## 목표

- `cargo run` 한 번으로 QEMU가 뜨고, 터미널에 커널이 찍은 문장이 보인다.
- 전원 직후 첫 명령어부터 문장이 찍힐 때까지 실행되는 코드가 모두 이 저장소에 있다.
- 각 코드가 왜 필요한지 사용자가 설명할 수 있다.

## 이번 단계에서 하지 않는 것

- 인터럽트·트랩 처리, 타이머
- 메모리 할당기, 가상 메모리(페이징)
- 멀티코어 (코어 1개만 사용)
- 키보드 입력, 그래픽 화면 출력
- 실제 보드에서 실행

## 피해야 할 것

- 동작은 하지만 사용자가 이해하지 못한 코드가 쌓이는 것
- 하드웨어를 가려 버리는 외부 크레이트에 의존하는 것

## 제약

- 개발 환경: Apple Silicon macOS, Rust stable 1.99.1, `qemu-system-riscv64` 설치됨
- 언어: Rust **[결정]**. 코드 주석·문서·커밋 메시지는 한국어, 식별자는 영어

## 검토한 방식

### CPU 아키텍처

| 방식 | 장점 | 단점 |
|---|---|---|
| **RISC-V 64** | 부팅이 단순, 개방형 표준이라 라이선스 제약 없음, xv6-riscv를 참고 기준으로 쓸 수 있음 | 실제 기기에서 돌려 보기 어려움 |
| x86_64 | 자료가 가장 많음, 실제 PC·서버와 동일 | 16→32→64비트 전환 등 호환성 유산이 많음 |
| AArch64 | 개발 기기와 같은 계열 | 권한 레벨 구조와 장치 트리가 처음엔 복잡 |

**[결정] RISC-V 64.** 라이선스 문제가 없고 실제로 활용할 수 있는 곳이 더 많다고 판단했다.
다른 아키텍처로 옮기려면 부팅·페이지 테이블·인터럽트·컨텍스트 스위칭을 다시 써야 한다는 점은 알고 선택했다.

### 부팅 시작 지점

| 방식 | 장점 | 단점 |
|---|---|---|
| **A. 펌웨어 없이 M 모드부터** | 전원 직후 모든 명령어가 내 코드, xv6-riscv와 같은 방식 | 실제 보드에 올릴 때 펌웨어 연동을 추가해야 함 |
| B. OpenSBI 위에서 S 모드부터 | Linux가 실제 보드에서 부팅되는 방식 | M 모드에서 일어나는 일이 가려짐 |

**[결정] A.**

## 설계

### 실행 환경

- 타깃: `riscv64gc-unknown-none-elf`
- QEMU: `virt` 머신, `-bios none`, 코어 1개, 메모리 128MB, `-nographic`(시리얼을 터미널에 연결) **[제안]**

### 부팅 흐름

```
QEMU 리셋 벡터(0x1000)
  → 0x80000000 `_start`      (어셈블리, M 모드)  스택 포인터 설정, .bss 0으로 초기화
  → `start()`                (Rust, M 모드)      S 모드로 내려갈 준비
  → `mret`
  → `kmain()`                (Rust, S 모드)      UART 초기화, 문장 출력, 대기 루프
```

`start()`가 M 모드에서 하는 일:

1. `mstatus`의 이전 권한 필드를 S 모드로 설정
2. `mepc`에 `kmain` 주소 기록
3. `satp`를 0으로 두어 페이징 끔
4. `medeleg`, `mideleg`로 예외·인터럽트를 S 모드에 위임
5. PMP를 열어 S 모드가 전체 메모리에 접근하도록 허용
6. `mret`로 S 모드 진입

타이머 설정은 인터럽트를 다루는 다음 단계로 미룬다. **[제안]**

### 구성 요소

| 파일 | 역할 |
|---|---|
| `src/entry.S` | `_start`: 스택 설정 후 Rust로 점프 |
| `kernel.ld` | 링커 스크립트: 시작 주소 `0x80000000`, 진입 코드를 맨 앞에 배치, 부트 스택 영역 정의 |
| `src/main.rs` | `#![no_std]`, `#![no_main]`, `start()`, `kmain()`, 패닉 핸들러 |
| `src/uart.rs` | NS16550A UART(`0x10000000`) 출력, `print!`/`println!` 매크로 |
| `.cargo/config.toml` | 기본 타깃, 링커 스크립트 지정, `cargo run` 시 QEMU 실행 |
| `rust-toolchain.toml` | stable 채널과 타깃 고정 |

파일 구성은 **[제안]** 이며 만드는 과정에서 조정할 수 있다.

### 그 밖의 선택 **[제안]**

- 외부 크레이트를 쓰지 않는다. CSR 접근은 인라인 어셈블리로 직접 작성한다. 레지스터를 직접 다뤄 보는 것이 학습 목적에 맞다.
- 빌드 도구는 `cargo`만 쓴다. Makefile은 두지 않는다.
- 패닉 시 메시지를 UART로 출력하고 멈춘다.

### 진행 방식 **[결정]**

- 작은 단계로 나누고, 각 단계는 눈으로 확인할 수 있는 결과로 끝낸다.
  예: 빈 커널이 멈춰 있음 → 어셈블리에서 글자 하나 출력 → Rust 진입 → S 모드 전환 → `println!`
- Claude가 코드를 작성하고, 단계마다 "왜 필요한지"를 설명한다. 사용자는 직접 실행해 확인한다.

## 완료 확인

- `cargo run` 실행 시 터미널에 커널 문장이 출력된다.
- 출력 시점의 권한이 S 모드임을 확인한다(GDB 또는 QEMU 모니터).
- 일부러 `panic!`을 넣으면 패닉 메시지가 출력된다.

## 만드는 사람에게 맡기는 것

- 단계의 정확한 분할과 순서
- 출력 문구, 함수·심볼 이름
- 부트 스택 크기
- 자동 확인 스크립트를 둘지 여부
