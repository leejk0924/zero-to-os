# zero-to-os 명세

## 무엇을

RISC-V 64용 운영체제 커널을 Rust로 처음부터 만든다. 왜 만드는지와 판단 기준은 `docs/intent.md`에 있다.

## 최종 목표

1. **(a)** 셸에서 디스크에 있는 사용자 프로그램을 실행한다.
2. **(b)** 사용자 프로그램으로 작성한 에코 서버가 `epoll`로 여러 연결을 동시에 처리하고, Mac에서 `nc`로 접속해 확인한다.

(b)를 달성하면 이 명세의 범위는 끝난다.

## 범위 밖

(b) 달성 뒤에 따로 정한다.

- 사용자 스레드(`CLONE_VM`, `futex`), 여러 코어를 쓰는 서버
- 마이크로커널 구조
- 직접 만든 TCP/IP 스택 (`smoltcp` 교체)
- ext2 저널링, `epoll` 엣지 트리거
- `musl` 포팅과 C 프로그램 실행
- 실제 보드에서 실행

## 로드맵

상태: `대기` → `설계` → `구현` → `완료`

| 단계 | 내용 | 끝났을 때 보이는 것 | 이슈 | 상태 |
|---|---|---|---|---|
| 1 | 부팅, 여러 코어 시작, UART, 첫 스핀락 | 코어 4개가 각자 `[S] hart N 시작` 출력 | #1 | 구현 (계획 승인 대기) |
| 2 | 트랩, 타이머 인터럽트 | 코어마다 주기적으로 틱 출력 | #2 | 대기 |
| 3 | 물리 메모리 할당기 | 페이지 할당·해제 테스트 통과 | #3 | 대기 |
| 4 | 가상 메모리(Sv39), 커널을 상위 절반으로 이동 | 페이징을 켠 뒤에도 커널이 정상 동작 | #4 | 대기 |
| 5 | 프로세스, 시스템 콜, 스케줄러, `clone`/`execve`, copy-on-write | 커널 이미지에 넣어 둔 사용자 프로그램 여러 개가 번갈아 실행 | #5 | 대기 |
| 6 | 블록 장치(virtio-blk), ext2 | 디스크 이미지의 파일을 읽고 씀, `e2fsck` 통과 | #6 | 대기 |
| 7 | 사용자 라이브러리, 셸 | 셸에서 디스크의 프로그램 실행 — 목표 (a) | #7 | 대기 |
| 8 | 네트워크 장치(virtio-net), `smoltcp`, 소켓 | Mac에서 `nc`로 접속해 연결 하나 에코 | #8 | 대기 |
| 9 | `ppoll`, `epoll`, 에코 서버 | 여러 연결 동시 에코 — 목표 (b) | #9 | 대기 |

- 각 단계는 시작할 때 따로 설계한다. 순서는 진행하며 바뀔 수 있다.
- 5단계까지는 사용자 프로그램을 커널 이미지에 넣어 두고, 6단계부터 디스크에서 읽는다.
- 네트워크는 QEMU 사용자 모드 네트워크의 포트 포워딩으로 Mac의 `localhost` 포트를 커널 쪽 포트에 연결한다.

## 개발 환경

- Apple Silicon macOS
- Rust stable (`rust-toolchain.toml`로 고정), 타깃 `riscv64gc-unknown-none-elf`
- `qemu-system-riscv64`, 머신 `virt`, 펌웨어 없음(`-bios none`)
